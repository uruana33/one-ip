# IP 质量样本验证

本工具用于离线复核真实响应、标签一致性和评分稳定性。目前只有一小组官方公共 DNS 用途标签，不具备重新训练风险权重的条件。

## 复跑现有快照

```sh
pnpm quality:evaluate
```

无需网络。输入位于 `scripts/ip-quality-data/labels.json`、`samples.json`，结果为 `docs/ip-quality-calibration-results.md` 和 `scripts/ip-quality-data/results.json`。相同输入与实现得到相同结果；报告保存实现哈希和输入哈希，未提交源码也会改变实现指纹。

## 重新采样

在本地开发服务已运行时，显式执行：

```sh
pnpm quality:collect
pnpm quality:evaluate
```

采集器从官方标签中读取地址，加上 `124.126.3.108`、`74.120.253.118` 两个未标注观察对象。每次最多 12 个地址，按地址顺序采集；每个地址的 Coffee 与本地交叉接口并发读取。已有 `samples.json` 会更新，使用其他输出路径可保留旧批次：

```sh
node scripts/ip-quality-collect.mjs --out /tmp/new-samples.json
node scripts/ip-quality-calibration.mjs --samples /tmp/new-samples.json --out /tmp/new-report.md --json /tmp/new-results.json
```

不自动重试或循环采样。失败会保留状态，不填零分；采集的只是评分所需字段，不保存整个上游档案、浏览器身份或账号信息。本地交叉接口的现有来源读取规则与超时策略仍适用。

## 标签规则

- 官方运营方明确列出的服务 IP 可以作为该服务用途标签。官方 DNS 标签不能用来断言无 VPN、无滥用或安全。
- 标签记录一手来源 URL、证据摘要、核对时间、运营方组和具体评价维度。正在被评估的供应商不能同时提供该地址的“正确答案”。
- 同一运营方多个 IPv4/IPv6 地址属于同一组。将来划分训练/验证集时，应按运营方及时间分组，不能随机拆同一运营方地址制造独立样本。
- 当前静态服务标签只与核对时间前后 30 天内的快照比较；有失效时间的标签还需在有效期内。评估优先使用交叉来源的 `cross.checkedAt`，缺失时才回退到采集器的 `collectedAt`。Tor 等快速变化标签默认使用 24 小时窗口，也可以在标签中用 `alignmentWindowHours` 配置更窄窗口，不能沿用静态 DNS 的时效假设。
- 未知目标不计入分类一致性；采集失败、时间不匹配、缺少快照单独报告，不能隐藏失败后宣称准确率。
- 这批官方公共 DNS 记录后来用于生产用途登记。报告把对应的比较标为 `catalogue-backed`，只检查登记规则，排除出独立准确率分母。未来新增独立验证样本需要避免与生产登记或调参样本复用。
- 顶层模型类别可能优先表达匿名/高风险信号。与公共服务标签出现分歧时，需要逐项审查其用途与风险两个维度，不能直接视为官方用途错误或认定供应商有误。

## 稳定性与调参边界

报告会逐一移除可用来源，并测试 IPinfo、IP2Location、Scamalytics 共同缺失的场景；这是考虑潜在数据家族关联的压力测试，不断言三者完全同源。还会在信誉与匿名维度之间转移最多 10 个百分点，观察结果敏感程度；范围不是置信区间，也不是建议的新权重。

`indicator-model-v4` 按当前策略保留部分数据下的数字评估：有效来源及已知维度重新归一，未返回字段仍为未知，并将结果标为估算。报告继续记录来源移除后的分差、用途/风险类别变化及估算状态；只有完全没有信誉或匿名信号才没有质量分。IPv6 的 IPPure 不适用。新旧结果应对照实现指纹与覆盖范围，不能只比较数值。

当前数据缺少住宅、企业/校园、机房和多类匿名出口的独立真值，也没有诈骗、滥用或平台业务结果标签。因此校准就绪状态始终为 false。只有补齐可靠的样本、冻结验证集、定义错误成本后，才能决定是否调整模型或权重。模拟回归测试验证代码性质，不能替代真实样本。
