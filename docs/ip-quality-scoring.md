# IP 信誉参考指数与证据规则

更新：2026-09-21。本文记录当前实现，替代旧分析文档中关于最终展示与评分的设计建议；历史问题见 `ip-quality-review-124.126.3.108.md`。

## 指标边界

页面展示的是本站规则定义的参考指数，不是欺诈概率、平台通过率、账号安全分或“全网纯净度”。当前尚无可靠真实标注样本的校准结果。各来源可能共享上游数据；“有效来源数”表示可用证据覆盖，不表示统计独立性或准确率。

评分改为七指标加权模型（策略版本 `indicator-model-v4`）。每项指标一个固定系数，Σ=1.00；指标无证据时保持 null 并剔除，其余系数按比例重归一化——未知项不填零分也不默认“干净”。

| 指标               | 系数 | 内容                                                                                     |
| ------------------ | ---- | ---------------------------------------------------------------------------------------- |
| 滥用记录 abuse     | 0.22 | DNSBL 列入数连续映射、AbuseIPDB 置信度、IPregistry 滥用旗标、Coffee 滥用等级             |
| 欺诈风险 fraud     | 0.18 | IPQS / Scamalytics / proxycheck / IP2Location 分档 + IPPure 纯净度，按源权重合成         |
| 匿名暴露 anonymity | 0.16 | 逐源匿名旗标共识；检出票权重 2.2×（检出是强证据、未检出是弱证据），Tor 命中权重 3×       |
| 用途属性 usage     | 0.14 | 住宅 100 → 移动 95 → ISP 88 → 公共服务 78 → 机构 68 → 机房 35 的连续映射，分歧自然落中段 |
| 网络归属 network   | 0.12 | trust_score 0.45 + asn_kind 0.30 + 托管旗标占比 0.25；单源旗标只算弱信号                 |
| 地理一致 geo       | 0.09 | 各源国家票众数占比（30 + 70×占比）；anycast/迁移段自然低分，非欺诈判决                   |
| 可溯源 integrity   | 0.09 | RDAP 注册记录存在性与 handle/cidr 完整性；注册日期仍只作展示上下文                       |

合成函数：`S = round(clamp(min(60 + min(1, E/0.75)·(B·P − 60), C), 0, 100))`

- `B = Σ(wᵢ·xᵢ)/Σwᵢ`：有证据指标的加权均值
- `P = Π pⱼ`：罚因子连乘——Tor 官方名单命中 ×0.12、滥用≤20 ×0.55、欺诈≤15 ×0.60、匿名≤25 ×0.70、匿名检出票多于完整阴性票 ×0.75、极端欺诈未被干净读数反驳且伴随匿名检出 ×0.80、匿名出口叠加滥用 ×0.75
- `C`：硬顶——Tor 名单 15 / 任一 Tor 命中 25 / 滥用方旗标、双源极端欺诈、或单一极端欺诈未被反驳且有外部匿名检出 → 25 / 住宅代理 35 / 匿名≤15 → 40 / 滥用≤15 或欺诈≤12 → 30
- 极端判决必须独立：一家来源不能用自己的匿名旗标为自己的极端欺诈分作证；任一其他欺诈/纯净/风险源映射后 ≥60 即构成反驳，孤立的极端指控只压低欺诈指标，不能封顶
- `E`：加权证据覆盖（各源信息量不同，见 `COVERAGE_WEIGHTS`）；E<0.75 时分数向中性 60 收敛，覆盖越薄越不作数
- 用途、地理等描述性指标不能凭空造分：滥用/欺诈/匿名/网络/可溯源全无证据时总分为 null

### 质量区间

页面不只展示一个分数，还展示 `range = {lo, hi}`——缺失指标分别按悲观/乐观锚点填充后，走与中心分相同的管线（同样的罚因子 `P` 与硬顶 `C`）得到的下界与上界：

| 指标     | 悲观锚点 | 乐观锚点 |
| -------- | -------- | -------- |
| 滥用记录 | 20       | 95       |
| 欺诈风险 | 15       | 92       |
| 匿名暴露 | 10       | 94       |
| 用途属性 | 35       | 100      |
| 网络归属 | 40       | 88       |
| 地理一致 | 30       | 100      |
| 可溯源   | 40       | 95       |

- 缺失不等于干净，也不等于灾难：锚点界定了"现有证据仍允许"的两端。
- 证据越薄区间越宽；七项指标全部有实测值且覆盖饱和时，上下界收敛到同一个点。
- 中性收敛（E<0.75 时向 60 收缩）只作用于中心分，不作用于区间——覆盖不足必须表现为更宽的区间，而不是被藏起来。
- 罚因子与硬顶同时压住上下界：Tor 命中时区间不会暗示"也可能很高"（如 `8–15`）；极端欺诈叠加匿名检出时整个区间都在 25 以下。
- 区间是"证据允许范围"，不是统计置信区间；中心分恒落在 `[lo, hi]` 内。

供应商原始数值、方向和用途标签仍分别展示。分档换算及用途偏好是本站规则，不能称为所有供应商认可的统一尺度。

## 未知与证据覆盖

- 匿名字段分别保留 true、false、unknown。VPN 否不能推导 Proxy/Tor 否；Hosting 否也不能推导非匿名。
- Worker 只输出实际读到的 `flags`。旧版仅包含 `No` 的扁平结果不再作为阴性依据；旧版明确的正向标签仍保留。
- 同一来源存在不同的信誉读数时，显示“信誉读数冲突”并排除其信誉投票；不能由数组顺序决定选择哪个数值。其它明确的匿名、用途事实仍单独保留。
- 完整的 VPN/Proxy/Tor 阴性组，或供应商明确的合并匿名阴性，才可作为该来源的匿名阴性证据。任一正向匿名标签均保留；不会被另一个未知字段覆盖。
- 信誉、匿名、用途分别列出有效来源。部分匿名阴性字段仍展示，但不能代替一组完整匿名检测。
- 部分来源未返回、某个信誉指标缺失或冲突时，其它有效读数继续参与计算；总分显示“估算”，数据覆盖与质量高低分别表达，不再因一家不可用隐藏总分。
- 信誉在实际已返回的有效供应商间按原相对权重归一；IPv6 的 IPPure、DNSBL、Tor 出口名单明确不适用（均为仅 IPv4 数据模型）。不同来源覆盖的估算分可能发生变化，不能把来源丢失后的涨分理解为质量真实改善。
- 匿名维只采用明确正向命中或完整阴性组/明确合并阴性。部分阴性字段仍不算完整阴性，缺失不代表“未检出”。Tor 出口名单只回答“是否 Tor”，其阴性既不算完整匿名阴性，也不抹掉其它命中。
- 指标本身未知时从综合公式中剔除，已知指标保持原系数比例后归一。页面计算说明展示每项指标的系数、实际生效权重与得分；Tor、住宅代理、滥用等硬顶继续生效。
- 状态分为 `ready`（覆盖达到现行规则）、`provisional`（有分数但存在缺失/有限证据）、`unavailable`（没有任何可用信誉或匿名信号）。这不是统计置信度。
- 顶部展示数字、结论、简短解释及一组最关键的依据对照。例如本次 IP 显示住宅/教育/商业用途的三源对照；完整摘要、缺失来源、采样时间、官方链接和公式放入“查看依据”。
- `checkedAt` 是本次交叉来源读取时间，不是各家数据库更新时间；目前没有取得供应商数据库更新日期。

## 用途与匿名结论

- 住宅、移动、ISP、企业/教育等机构、数据中心和公共服务分别建模。
- 住宅与机构、住宅与移动、数据中心与其他用途冲突时，明确列出来源及用途分歧。Coffee 内部用途冲突也保留。
- 数据中心是用途类别，不是欺诈判决。机房票把用途指标压向 35 并通过 0.14 系数拖低综合分，但任何情况下都不再单独封顶总分；干净的机房 IP 仍可得高分。
- 组织/ASN 归属不再额外充当另一家独立用途票。来源用途标签仍不能代替线路运营方或现场接入证据。
- VPN、Proxy、Tor、Relay、住宅代理和未分类型匿名命中共享同一份归一信号，供卡片、分类、摘要和评分使用。匿名/中继特征不等同于恶意行为。
- IP-API 的合并 proxy 旗标不能确认为某一种 VPN 技术。
- 注册国与定位国相同时直接陈述这个事实，不再据此证明“原生 IP”。
- 增加独立维护的官方公共 DNS 用途登记，目前仅含已核实的 8 个精确地址，不匹配 ASN 或整个网段。页面和复制报告展示运营方链接及核对日期；登记自核对起 180 天有效，过期或查询时间早于核对时不使用。归一化使用项目已有的严格 IP 解析。
- 官方登记只保持公共服务用途与相应用途分支，不增加信誉、匿名或供应商用途票数；匿名与滥用命中优先于公共服务标签。只有官方用途记录、没有信誉或匿名信号时不造分。

## 来源覆盖

Worker `/api/ip/cross/{ip}` 自动读取的来源（只列原始读数，不在服务端混合）：

| 来源           | 读数                                                      | 覆盖                                                                                               |
| -------------- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| IPPure         | 纯净度（100 − 蜜罐风险分）                                | IPv4；签名握手首个 `ok:false` 响应自动重试一次                                                     |
| IP2Location    | 欺诈分、Proxy/Proxy Type、用途类型                        | 页面 `Proxy` 字段在 `Proxy Type` 为 `-` 时兜底                                                     |
| IPinfo         | 隐私旗标、公司类型、地理位置                              | 页面                                                                                               |
| IP-API         | proxy/hosting 旗标、用途、地理位置                        | 免费 JSON                                                                                          |
| proxycheck     | 风险分、匿名类型、用途、地理位置                          | 免费 JSON                                                                                          |
| Scamalytics    | 欺诈分、匿名、用途                                        | 页面；机房出口常 403，失败记 unavailable                                                           |
| DNSBL          | 30 个公开滥用名单的列入数                                 | IPv4；经 Cloudflare DoH 查询，整组查询失败不当作"干净"                                             |
| Tor 出口名单   | 官方出口地址是否命中                                      | IPv4；check.torproject.org 公布列表                                                                |
| IPregistry     | abuser/attacker/threat 旗标、匿名旗标、连接类型、地理位置 | 优先用 `IPREGISTRY_API_KEY`；未配置回退站点公开 demo key（共享配额限流或轮换时如实记 unavailable） |
| IPQualityScore | 欺诈分、匿名旗标、用途、地理位置                          | 仅配置 `IPQS_API_KEY` 时请求                                                                       |
| AbuseIPDB      | 滥用置信度、举报数、用途、Tor                             | 仅配置 `ABUSEIPDB_API_KEY` 时请求                                                                  |

- DNSBL 名单只保留已验证经公共 DoH 应答、且"列入"即滥用语义的 IPv4 区；白名单、信誉分档、按地域整段列入和 Tor 枚举区不计入（列入不等于滥用）。
- 未配置 key 时 IPQS / AbuseIPDB 不发请求、不计入 unavailable，页面保持"去原站"外链卡片；配置了 key 但读取失败则按 unavailable 处理。
- 信誉换算保持分来源语义：IPQS 欺诈分沿用其官方分档（<75 低、75–84 可疑、85–89 高风险、90+ 欺诈）；AbuseIPDB 置信度 0 为无举报、25+ 起有举报背书；DNSBL 连续映射 `97 − 21·列入数 − 40·列入比例`（零星列入常见，广度才是风险）；IPregistry 任一滥用旗标命中 → 25，干净 → 90。任一数值都只描述该来源自己的口径。
- DNSBL 与 Tor 名单没有地理字段，不参与位置共识表。

## 场景测量

平台星级描述当前浏览器访问公开端点的 HTTP 速度。总览按平台显示与查询 IP 一致、不同和未核验的出口数。不同出口保留本浏览器的速度结果，但不能作为查询 IP 的平台可用性证据。没有登录、对话、交易或播放成功的推论。

## 回归与后续校准

已建立第一批 10 条真实响应快照，其中 8 条有官方公共 DNS 用途标签，覆盖 3 个运营方。相同官方记录现在进入生产用途登记，因此报告将这 8 条改为“登记规则检查”，排除出独立准确率分母。可运行 `pnpm quality:evaluate` 离线复跑，查看 [试验结果](./ip-quality-calibration-results.md) 和 [采样与标签规则](./ip-quality-calibration.md)。修复前的结果冻结在 `scripts/ip-quality-data/baseline-coverage-v1.json`；不能把暂停评分记成零波动，也不能把登记查表一致性宣称为模型泛化能力。

回归用例覆盖部分字段缺失、旧版 No、机构用途冲突、只有信誉/用途而没有匿名数据、Proxy/Tor/Relay 命中、孤立 Tor 命中、信誉来源不足、外部来源缺失以及 RDAP 年龄不改变评分。场景测试覆盖平台级出口归属及 mismatch 不变成失败。

后续校准需另外准备有可信用途标签、采样时间与来源版本的真实 IP 数据集，区分住宅、企业/校园、机房和各类匿名出口；用独立验证集评估用途误判和风险指标，才能有依据调整权重。模拟回归样本不能充当真实用途标签，也不能用于宣称准确率。
